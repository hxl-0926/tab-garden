# 怎样从这个工具学到东西

## 先用 5 分钟

收下自己真正想读的三条链接。给每条留一句“我为什么想读”，再点“给我一点灵感”。读一篇，标记完成。不要把整理收藏变成新的拖延方式。

## 1. 纯函数和边界

阅读 `src/core.mjs`：为什么两个带不同 `utm_source` 的 URL 可以视为重复，但 `#chapter-1` 和 `#chapter-2` 不应该直接合并？为什么保留其他参数的顺序？通过自己的反例理解保守归一化。

## 2. 浏览器状态会变

阅读 `duplicatePlan` 与 `revalidatePlan`。一个标签页从预览到确认之间，可能被用户切换、固定或导航到其他页面。计划里的 URL 和当前 URL 必须再次核对。进一步思考为什么“查询后关闭”仍无法做到完全原子。

## 3. 有状态程序如何可靠保存

阅读 `src/service.mjs`。同时发出 30 次保存，不应该只剩最后一次结果。串行队列把 read-modify-write 放在同一个服务里。写入快照失败时为什么必须阻止后续关闭？队列里的一个失败为什么不能让所有操作都失败？

## 4. 模型和平台之外的测试

平台 API 在 `background.mjs` 注入，测试使用内存适配器，演示使用 localStorage 适配器。检查它们分别验证了什么，又有哪些真实 Chrome 行为必须通过加载扩展确认。模拟平台通过不等于真实浏览器 API 已经通过。

## 5. 可以自己完成的升级

1. 加入标签编辑与收藏排序，不改变导入导出格式。
2. 为快照保存分组元信息，恢复到新窗口后重建分组。
3. 增加搜索高亮，用 DOM 节点处理文本而非拼接 HTML。
4. 实现 IndexedDB 存储适配器，比较队列、事务和存储配额的关系。
5. 添加可选本地语义搜索，先说明会使用哪些数据，再与纯词项搜索做评测。
